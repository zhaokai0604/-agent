# ThreshCore 固定演示数据

本目录对应 `threshcore-demo-v1`，用于比赛演示、回归测试和演示视频录制。演示只允许在临时目录中运行，不要把真实 `/var/log` 或生产目录作为目标。

## 演示步骤

1. 将 `src/test/resources/demo/threshcore-demo.log` 复制到临时演示目录，并额外创建三个固定文件：`app.log.20240101`、`mysql-slow.log`、`audit.log`。
2. 先调用 `LogCleanupTool` 的 dry-run，预期看到 `filesFound=3`、`deletableCount=1`、`protectedSkipped=2`。
3. 通过 Agent 或 MCP 发起真实处置，必须经过统一 PEP 入口；预期执行结果包含 `recycledCount=1`、`recycleHandles`、`protectedFilesPreserved=true`。
4. 管线自动执行一次 dry-run 复测，预期 `metricsBefore.deletableCount=1`、`metricsAfter.deletableCount=0`，并且 `metricsDelta.deletableCount=-1`。
5. 使用返回的 `recycleHandles[0]` 调用 `recycleBinOps(operation=restore, handle=...)`，预期 `restored=true`，原文件恢复且回收站条目消失。

## 固定验收点

- 受保护文件只进入 `protectedSamples`，不得出现在 `recycleHandles`，并由 `protectedFilesPreserved=true` 做执行后断言。
- 回收站移动失败时必须 fail-closed，不能回退成 `rm -f` 或 `Remove-Item`。
- Agent、MCP、巡检自动修复的真实写都应产生 `traceId`、`metricsBefore`、`metricsAfter`、`metricsDelta`、`verifyOutcome` 和恢复信息。
