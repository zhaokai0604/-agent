## 2. 实验范围与边界

- 实验对象为当前 V1 的本地功能/安全切片，运行在 Windows 单机开发环境。
- 故障诊断、工具选择使用当前确定性规则和工具目录进行可重复验证，不等同于外部 LLM 的诊断准确率或工具选择基准。
- 恶意日志注入验证工具输出扫描与统一调用门禁，不声称复现真实外部攻击成功率。
- 效果验证验证执行证据契约的三种状态：已验证、证据不完整、验证失败；不将合成证据映射写成生产环境端到端写入结果。
- 涉及写入的探针只操作 JUnit 临时目录，不操作生产目录、真实数据库或用户数据；未接入外部模型。
- 本次结果不替代麒麟 V11 / LoongArch 目标机验收，也不构成多节点或生产部署证明。

## 4. 案例级证据摘要

### E-APP-01 故障诊断

`FD-01` 验证自然语言中的故障诊断意图与时间范围；`FD-02`、`FD-03` 分别验证 `nginx`、`kafka` 目标服务抽取。三例均通过。

### E-APP-02 工具选择

`TS-01`、`TS-02` 验证日志清理和临时文件清理的场景路由；`TS-03` 验证泛化系统状态请求保持只读；`TS-04` 验证 CPU 请求包含负载与进程观测工具；`TS-05` 验证已注册 HTTP 工具目录完整性。

### E-APP-03 恶意日志注入

`MI-01` 验证英文间接注入被检测并在调用门禁阻断；`MI-02` 验证中文间接注入被检测；`MI-03` 验证正常诊断输出不被标记。

### E-APP-04 越权阻断

`PB-01` 阻断未知工具，`PB-02` 阻断只读工具面上的写工具，`PB-03` 阻断破坏性 Shell，`PB-04` 阻断对数据库数据目录的日志清理。

### E-APP-05 效果验证

`EV-01` 验证具备删除证据的结果进入 `VERIFIED`；`EV-02` 验证缺少证据时进入 `EVIDENCE_INCOMPLETE`；`EV-03` 验证保护文件未保持时进入 `VERIFY_FAILED`。

### E-APP-06 恢复成功

`RC-01` 在临时目录创建文件，调用回收站服务完成移动、句柄生成、原内容恢复和一致性检查；`RC-02` 验证伪造路径穿越句柄不能恢复。
