# ThreshCore（award-log）部署文档

**部署方式**：Fat Jar 后端 + Nginx 反向代理前端与 API

| 项 | 说明 |
|----|------|
| **系统名称** | ThreshCore 控制台 + award-log 后端 |
| **Context Path** | `/award-log` |
| **对外端口** | Nginx `80` / `443`（用户访问） |
| **后端端口** | `8088`（仅本机，由 Nginx 反代，不对外暴露） |
| **技术栈** | Java 17 · Spring Boot 3.5 · Vue 3 · MySQL 8 · Nginx |
| **文档版本** | 2026-06-06 |

## 1. 部署架构

```
用户浏览器
    │
    ▼
Nginx :80 / :443          ← 唯一对外入口
    ├── /                 → /opt/threshcore/dist/（Vue 静态资源）
    └── /award-log/       → 反代 http://127.0.0.1:8088/award-log/
                                │
                                ▼
                         award-log.jar（systemd 托管，仅监听本机）
                                │
                                ├── MySQL 8（必选）
                                └── 通义千问 API（AI 助手需要）
```

**要点**：

- 后端以 **Fat Jar** 运行，由 **systemd** 托管，监听 `127.0.0.1:8088`，不直接对外。
- 前端 `dist/` 由 **Nginx** 托管；浏览器所有 API 请求走同域 `/award-log/`，避免跨域。
- MCP 工具需访问宿主机路径与进程，**不将应用本身放入 Docker**。
- Kafka、Redis、Elasticsearch 默认关闭，无需部署。

## 3. 快速部署（五步）

在**运行机**上按顺序执行：

```bash
# ① 构建（或在 CI 机构建后上传 deploy/release/ 目录）
PROD_BUILD=1 bash scripts/deploy/deploy.sh

# ② 初始化数据库（首次）
mysql -u threshcore -p log_analysis < src/main/resources/schema.sql

# ③ 安装 Jar + 环境变量 + systemd
sudo mkdir -p /opt/threshcore/logs /etc/threshcore
sudo cp deploy/release/award-log.jar /opt/threshcore/
sudo cp -r deploy/release/dist /opt/threshcore/
sudo cp scripts/deploy/env.kylin.prod.example /etc/threshcore/threshcore.env
sudo chmod 600 /etc/threshcore/threshcore.env
# 编辑 /etc/threshcore/threshcore.env，填写 DB_PASSWORD、AI_API_KEY
sudo cp scripts/deploy/award-log.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now award-log

# ④ 配置 Nginx
sudo cp scripts/deploy/nginx.sample.conf /etc/nginx/conf.d/threshcore.conf
# 修改 server_name、root 为 /opt/threshcore/dist
sudo nginx -t && sudo systemctl reload nginx

# ⑤ 验收（经 Nginx，非直连 8088）
curl -s http://127.0.0.1/award-log/actuator/health
curl -s http://127.0.0.1/award-log/api/platform/info
# 浏览器打开 http://<服务器IP>/
```

## 4. 构建 Jar 与前端静态资源

### 4.1 前端构建前：配置 API 地址

Nginx 同域部署时，**构建前**必须创建 `frontend/.env.production`：

```bash
# 将 your.domain.example 替换为实际域名或 IP
VITE_AWARD_LOG_BASE_URL=http://your.domain.example/award-log
```

> 未设置此变量时，前端会请求 `域名:8088/award-log`，经 Nginx 反代后将导致 API 失败。

### 4.2 执行构建

**Linux / macOS：**

```bash
# 生产构建（强制执行测试）
PROD_BUILD=1 bash scripts/deploy/deploy.sh
```

**Windows PowerShell：**

```powershell
$env:SKIP_TESTS='0'; .\scripts\deploy\deploy.ps1
```

### 4.3 产物

| 文件 | 用途 |
|------|------|
| `deploy/release/award-log.jar` | 后端 Fat Jar，交给 systemd |
| `deploy/release/dist/` | 前端静态资源，交给 Nginx `root` |
| `deploy/release/nginx.sample.conf` | Nginx 配置参考 |

将 `deploy/release/` 整个目录上传至运行机（scp、rsync 或 CI 制品库均可）。

## 5. 配置环境变量

复制模板并编辑：

```bash
sudo mkdir -p /etc/threshcore
sudo cp scripts/deploy/env.kylin.prod.example /etc/threshcore/threshcore.env
sudo chmod 600 /etc/threshcore/threshcore.env
sudo vim /etc/threshcore/threshcore.env
```

**通用生产（x86 / Linux）最小配置：**

```bash
SPRING_PROFILES_ACTIVE=prod

DB_URL=jdbc:mysql://127.0.0.1:3306/log_analysis?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
DB_USERNAME=threshcore
DB_PASSWORD=<填写>

AI_API_KEY=<填写>
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode

AGENT_RUN_AS_USER=award-agent
AGENT_MIN_PRIVILEGE=true
APP_AI_AUDIT_RELAXED_READ=false

AWARD_MIDDLEWARE_KAFKA=false
AWARD_MIDDLEWARE_REDIS=false
ELASTIC_ENABLED=false
```

> 环境变量由 systemd `EnvironmentFile` 加载，见 `scripts/deploy/award-log.service`。勿将含密钥的文件提交 Git。

## 6. 数据库初始化

### 6.1 建库与用户


### 6.2 建表

```bash
mysql -u threshcore -p log_analysis < src/main/resources/schema.sql
```

## 7. 部署 Jar 包（systemd）

### 7.1 安装

```bash
sudo mkdir -p /opt/threshcore/logs
sudo cp deploy/release/award-log.jar /opt/threshcore/
sudo cp scripts/deploy/award-log.service /etc/systemd/system/

sudo systemctl daemon-reload
sudo systemctl enable award-log
sudo systemctl start award-log
```

### 7.2 验证 Jar 已启动（本机）

```bash
# 仅用于排查，生产用户不直连此端口
curl -s http://127.0.0.1:8088/award-log/actuator/health
sudo journalctl -u award-log -n 50 --no-pager
```

启动成功标志：日志无 `[prod] 未配置数据库密码` 报错，`health` 返回 `UP`。

### 7.3 常用运维命令

```bash
sudo systemctl status award-log
sudo systemctl restart award-log
sudo journalctl -u award-log -f
```

### 7.4 最小权限用户（Linux 生产推荐）

```bash
sudo useradd -r -s /sbin/nologin award-agent
# 配置 sudoers，详见 README.md 安全章节
```

## 8. 配置 Nginx 反向代理

### 8.1 安装静态资源

```bash
sudo cp -r deploy/release/dist /opt/threshcore/
```

### 8.2 写入 Nginx 配置

```bash
sudo cp scripts/deploy/nginx.sample.conf /etc/nginx/conf.d/threshcore.conf
```

编辑 `/etc/nginx/conf.d/threshcore.conf`，至少修改：

- `server_name` → 实际域名或 `_`
- `root` → `/opt/threshcore/dist`

### 8.3 完整配置参考

```nginx
server {
    listen 80;
    server_name threshcore.example.com;   # 改为实际域名或 IP

    root /opt/threshcore/dist;
    index index.html;

    # 前端 SPA 路由
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反代（Jar :8088，仅本机）
    location /award-log/ {
        proxy_pass http://127.0.0.1:8088/award-log/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # WebSocket（顶栏性能、巡检告警）
    location /award-log/ws/ {
        proxy_pass http://127.0.0.1:8088/award-log/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    # 生产建议：禁止公网访问接口文档与 Actuator
    location /award-log/doc.html { deny all; return 403; }
    location /award-log/actuator/ { deny all; return 403; }
    location /award-log/swagger-ui/ { deny all; return 403; }
}
```

### 8.4 启用配置

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 8.5 HTTPS（生产对外服务）

在 `server` 块前增加 80 → 443 跳转，并配置 `ssl_certificate` / `ssl_certificate_key`（Let's Encrypt 或企业证书）。构建前端时 `VITE_AWARD_LOG_BASE_URL` 须改为 `https://...`。

### 8.6 访问地址

| 地址 | 说明 |
|------|------|
| `http://<域名>/` | 控制台首页（经 Nginx） |
| `http://<域名>/award-log/api/platform/info` | 平台信息（无需登录） |
| `http://127.0.0.1:8088/award-log/...` | **仅本机排查**，不对用户开放 |

## 9. 上线验收

### 9.1 经 Nginx 的基础检查

```bash
# 健康（若 Nginx 未 deny actuator，否则改查本机 8088）
curl -s http://127.0.0.1/award-log/actuator/health

curl -s http://127.0.0.1/award-log/api/platform/info

# AWM 冷启动 seed
curl -s "http://127.0.0.1/award-log/api/ops/workflow/memory?domain=all"
```

### 9.2 浏览器功能冒烟

1. 打开 `http://<域名>/`，登录控制台
2. Tab 1：输入「磁盘满了」→ 返回 Playbook 报告
3. Tab 2：`DiskTool` 可执行
4. Tab 4：链路审计可见六步 CoT；记忆层有 6 条 seed workflow
5. Tab 8：效果评分五维雷达有数据
6. 顶栏「安全自检」→ 探针 PASS

### 9.3 写操作护栏

- 「预览清理临时文件」→ 二次确认后仍为 dry-run
- 破坏性话术 + 只读工具 → `INTENT_TOOL_MISMATCH`

## 12. 升级与回滚

### 升级

```bash
# 1. 构建新版本（注意 frontend/.env.production 域名不变）
PROD_BUILD=1 bash scripts/deploy/deploy.sh

# 2. 停服、备份、替换
sudo systemctl stop award-log
sudo cp /opt/threshcore/award-log.jar /opt/threshcore/award-log.jar.bak
sudo cp deploy/release/award-log.jar /opt/threshcore/
sudo cp -r deploy/release/dist /opt/threshcore/

# 3. 启服、重载 Nginx
sudo systemctl start award-log
sudo nginx -t && sudo systemctl reload nginx
```

### 回滚

```bash
sudo systemctl stop award-log
sudo cp /opt/threshcore/award-log.jar.bak /opt/threshcore/award-log.jar
sudo systemctl start award-log
```

### 急停写操作

在 `threshcore.env` 中设置 `OPS_AUTO_REMEDIATION_ENABLED=false`、`OPS_DRY_RUN_GLOBAL=true`，然后 `systemctl restart award-log`。

### 数据库备份

```bash
mysqldump -u threshcore -p log_analysis > backup_$(date +%Y%m%d).sql
```

## 15. 常见问题

| 现象 | 处理 |
|------|------|
| 页面能开但 API 全失败 | 检查构建时 `VITE_AWARD_LOG_BASE_URL` 是否为 `http(s)://域名/award-log`（无尾斜杠） |
| Nginx 反代 404 | `proxy_pass` 末尾须为 `http://127.0.0.1:8088/award-log/`（含 `/award-log/`） |
| 前端 401 | 确认经 Nginx 同域访问；Cookie 需 `withCredentials`（前端已默认开启） |
| Jar 启动退出 | 检查 `DB_PASSWORD`；`journalctl -u award-log` 看报错 |
| WebSocket 断开 | 确认 Nginx 配了 `location /award-log/ws/` 及 Upgrade 头 |
| AI 无回复 | 配置 `AI_API_KEY` |
| AWM 套路为空 | 确认 `schema.sql` 已执行；`GET /award-log/api/ops/workflow/memory` |
| 直连 8088 能访问、域名不行 | 前端 `VITE_AWARD_LOG_BASE_URL` 未按 Nginx 域名配置，需重新 `npm run build` |
