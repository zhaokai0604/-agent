# ThreshCore V1 产品化封口清单

> **范围**：单机信安/运维助手平台（本机运维工具执行），**不包含**多机 Fleet、远程 Node、AWVS/OpenVAS 等 v2 能力。  
> **封口定义**：可按本文完成构建、部署、演示、验收，且交付 API 白名单全部可用。
> **产品收敛**：ThreshCore = 受控处置运行时；封核主线见 [`五场景受控处置闭环对照表.md`](./五场景受控处置闭环对照表.md)。V1 工程封口通过后，迭代优先补齐五场景「敢执行、能证明、能恢复」，不新开能力面。

---

## 一、产品边界（v1 做什么 / 不做什么）

| v1 包含 | v1 不包含（记入 v2 路线图，暂不开发） |
|---------|--------------------------------------|
| 单机助手对话 + 巡检 + 自动处置 | Hub 管多台主机、Node Agent 联邦 |
| 28 个运维工具（本机执行） | 远程 SSH/`remote_host` 表落地 |
| PEP 预览→HMAC 确认→执行→验证 | 全集群策略下发 |
| 日志分析（Drain + RF/启发式） | nmap/AWVS/OpenVAS 扫描编排 |
| 麒麟 V11 + LoongArch 交付 | 分布式多实例水平扩展 |
| 安全自检、审计 trace、知识库 | 内置靶场一键部署 |

## 四、5 分钟 Golden Path（答辩 / 客户演示脚本）

按顺序操作，**全程可截图留档**：

1. **登录** → 仪表盘有数据（`GET /admin/statistics/log-summary`）
2. **平台状态** → TopBar / 环境页 `deliveryTargetMatch`（麒麟机为 true）
3. **安全自检** → 安全驾驶舱 / 自检弹窗，`overallStatus` 为 PASS 或已知 WARN 可解释
4. **日志分析** → 上传小日志 → 报告 → 可选 AI 诊断
5. **Agent 对话** → 「磁盘压力大」→ 只读观测 → 生成处置计划 → **确认执行**（若有写工具）
6. **MCP 控制台** → `DiskTool` 只读成功 → `CleanTempTool` dry-run 预览 → 二次确认（展示 `confirmToken` 流程）
7. **巡检** → 手动巡检或态势墙有更新
8. **审计** → 用 traceId 在审计中心 / 运维链路查到上述步骤

- [ ] 上述 8 步在目标环境各走通一次
- [ ] 录屏或截图文件夹已整理（建议目录名 `交付素材/YYYY-MM-DD/`）

## 八、已知可接受项（封口时不算缺陷）

## 九、封口完成标准（Definition of Done）

当且仅当以下全部满足，可声明 **V1 产品化封口完成**：

1. `mvn verify` + 前端 `build` 通过  
2. Golden Path 8 步在演示环境跑通并有留档  
3. 交付 API 白名单核心接口可用  
4. （若赛题交付）麒麟机 `smoke_kylin_acceptance.sh` 通过 + 检查清单 §PEP 已核对  
5. 团队一致同意：**v1 内不再新增架构级功能**（Fleet/扫描器/Fleet 表实现），缺陷修复与小 UX 抛光除外
