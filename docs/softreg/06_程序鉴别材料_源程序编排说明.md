# 程序鉴别材料源程序编排说明

## 一、编排目的

本说明用于解释 [06_程序鉴别材料_源程序前后各连续30页.txt](./06_程序鉴别材料_源程序前后各连续30页.txt) 的生成方式、代码来源与页数规则，便于核验其符合软著登记中程序鉴别材料的组织要求。

## 二、官方依据

根据《计算机软件著作权登记办法》第十条：

- 程序和文档的鉴别材料应当由源程序和任何一种文档 `前、后各连续30页` 组成
- 整个程序和文档不足 60 页的，应提交整个源程序和文档
- 除特定情况外，程序每页不少于 50 行

依据链接：

- https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html

## 三、本项目的真实代码范围

本次程序鉴别材料只选取本项目 `自研主程序代码`，不包含第三方依赖、`node_modules`、构建产物和文档文件。

纳入范围：

- `src/main/java/**/*.java`
- `frontend/src/**/*.js`
- `frontend/src/**/*.vue`

不纳入范围：

- `node_modules`
- `target`
- `docs`
- `outputs`
- 第三方下载依赖

## 四、编排顺序

为保证“前后连续页”来自同一套完整源程序序列，本次先将全量自研代码按固定顺序拼接为一份主源程序序列，再从该序列中截取：

1. 第 1 至第 1500 行，作为前 30 页
2. 最后 1500 行，作为后 30 页

主源程序序列排序规则如下：

1. `src/main/java/com/award/log/AwardWinningLogApplication.java`
2. `src/main/java/**/*.java` 按相对路径升序
3. `frontend/src/main.js`
4. `frontend/src/**/*.{js,vue}` 按相对路径升序

## 五、页数与行数规则

- 每页正文固定编排 `50` 行源程序
- 前 30 页共 `1500` 行
- 后 30 页共 `1500` 行
- 总计交存 `3000` 行真实源程序

## 六、行内容格式

每一行采用如下格式：

`全局行号  文件相对路径:文件内行号  源代码内容`

示例：

`000001  src/main/java/com/award/log/AwardWinningLogApplication.java:0001  package com.award.log;`

这样做的目的：

- 能证明每一行都来自真实项目代码
- 方便回溯到原始文件
- 方便登记前复核

## 七、自动生成方式

本材料由脚本自动生成：

- [scripts/softreg/generate_softreg_source_material.py](../../scripts/softreg/generate_softreg_source_material.py)

同时生成的辅助文件：

- [06_程序鉴别材料_源程序编排清单.json](./06_程序鉴别材料_源程序编排清单.json)

该 JSON 文件包含：

- 软件名称
- 版本号
- 编排规则
- 总文件数
- 总行数
- 纳入编排的文件清单

## 八、提交前复核建议

正式提交前，建议人工复核：

1. 程序鉴别材料中的第一页是否确为主程序开头部分
2. 程序鉴别材料中的最后一页是否确为主程序结尾部分
3. 代码版本是否与准备申报的版本一致
4. 是否误纳入第三方代码或临时测试代码
5. 若后续代码有大改，是否需要重新生成
