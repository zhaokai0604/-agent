# ThreshCore 初赛文档截图补拍清单

## 1. 使用原则

- 本清单只列当前初赛文档中 **必须由真实运行界面或真实终端替换** 的图片。
- `功能需求文档` 和 `功能设计文档` 以结构图、流程图、架构图为主，当前不要求你额外补拍照片。
- `产品说明书`、`功能测试报告`、`性能测试报告`、`部署文档` 中存在多张 `ph_*` 占位图或“截图/终端待补”位置，这些是本轮优先替换对象。
- 一张真实截图尽量复用到多份文档，避免重复裁图。

## 2. 建议交付方式

- 统一裁成 `PNG`
- 页面截图优先保留核心业务区域，不要保留浏览器多余标签栏
- 终端截图尽量只保留关键输出区域，不要截整屏桌面
- 敏感信息必须打码：密码、密钥、内网真实账号、IP 如不宜公开也建议打码

建议你把裁好的图按下面文件名放到一个目录里，后续我可以直接批量替换。

## 6. 最省事的补图顺序

如果你想先用最少工作量把文档从“占位图版”推进到“可提交版”，优先裁这 8 张：

1. `S01` 登录页

3. `S04` MCP 工具控制台

6. `S08` 日志分析

## 7. 当前判断

- 真实统计图可以继续用：测试通过率、测试分层、需求追踪、性能维度、上传耗时、WebSocket 对比等。
- 当前最不适合直接交付的是 `ph_login`、`ph_agent`、`ph_mcp`、`ph_security`、`ph_trace`、`ph_log`、`ph_livewall`、`ph_selfcheck` 这类占位图。
- 部署文档必须补一组 **8088 单端口生产部署证据图**，这样才能和“严格按项目实际”保持一致。
