| 一句话 | **自然语言运维麒麟主机；白名单执行、危险拦截、全程可追溯** |
| 片核 | 能干活 → 控得住 → 留得下 |

## 一、项目能力地图（拍什么 / 不拍什么）

### 必拍（对齐赛题 + 项目主链）

| 赛题要求 | 项目对应 | 视频落点 |
|----------|----------|----------|
| OS 深度感知 | `OsInsightTool` / Disk / Process / SystemLoad / Systemd 等 MCP | 对话查磁盘负载 + 工具台一瞥 |
| MCP 插件化 | `McpToolCatalog` + 26 Tools + 工具控制台 | 白名单列表 + 一次只读调用 |
| 安全意图校验 | `McpInvocationSecurityGate` 多级门控 | 预览确认 + 注入/高危 BLOCK |
| 最小权限 | `AGENT_MIN_PRIVILEGE` + 路径策略 `OpsPathPolicy` | 口播 + 配置/自检一镜 |
| 推理链路溯源 | `ops_audit_trace` 六步 CoT | **运维链路审计**页（快捷键 4） |
| 抗注入 / 确定性 | PromptInjection / 高危命令 / 路径白名单 | 拦截镜头 |
| 信创 | `prod-kylin` / LoongArch 部署 | 环境状态或实机 5～8 秒 |

### 选拍（证明「整体产品」但不抢戏）

| 模块 | 入口 | 镜头上限 |
|------|------|----------|
| 有界巡检 + 待确认修复 | `一键巡检` / 巡检相关页 | 20s |
| AWM / Reflexion | 链路审计中的记忆 / workflow memory | 15s |
| 日志分析或效果评分 | 快捷键 5 或 8 | 12s（二选一） |
| 安全自检 | 顶栏/安全自检 | 8s |
| 知识库 RAG | knowledge | 可不拍，口播一句即可 |

### 不拍（避免稀释）

- 26 个工具逐一点  
- 个人中心、用户管理、长配置 YAML  
- 贬低其他队伍、无法证实的商用合同  
- 真去执行破坏性删除「证明危险」

## 四、逐镜脚本（画面 · 操作 · 口播 · 字幕）

### 镜 1｜开场（35s）

**画面**：标题卡 `ThreshCore`；关键词 `误删` `注入` `需要护栏`；赛题名一行。

**口播**：

> 企业运维常常卡在两难：脚本门槛高，盯不住；把执行权交给 AI，又可能误删库、误操作。  
> 赛题要求在麒麟操作系统上，做一套智能运维 Agent：用 MCP 让大模型能感知、能执行，更要用安全护栏解决不可控。  
> ThreshCore 的答案是一句话：**自然语言能运维，危险操作控得住，全过程留得下。**

**字幕**：`能干活 · 控得住 · 留得下`

---

### 镜 2｜整体架构（30s）

**画面**：三层示意（海报即可，停 8～10s）：

```text
交互层：Agent 对话 │ MCP 工具台 │ 审计 / 态势
编排与安全：意图路由 │ 多级门控 │ 治理准入 │ 路径策略
执行与沉淀：白名单 MCP │ 最小权限 │ 六步审计 │ AWM / Reflexion
```

**口播**：

> 系统是 B/S 架构。对话编排、HTTP 工具调用、巡检自动修复，三条路径都进同一套安全门控。  
> 我们不给大模型开放 root Shell，只给白名单 MCP 工具。  
> 写操作默认预览；风险达标后，需要用户发送确认口令，才能真实执行；全程审计落库。

**字幕**：`统一安全门控 · 非开放 Shell` · `预览 → 确认 → 执行`

---

### 镜 3｜控制台总览（30s）

**操作**：进入工作台；鼠标轻划：`1 Agent` → `2 MCP` → `3 审计` → `4 链路审计` → `5 日志` → 环境状态；回到 Agent。

**口播**：

> 这是统一运维控制台：日常用智能对话；精细操作用工具台；追责复盘用审计与链路溯源。  
> 日志分析、效果评分、知识库等是完整产品能力，本片主线仍聚焦赛题：感知、MCP、护栏、溯源。

**字幕**：`一站式工作台 · 赛题主线优先`

---

### 镜 4｜OS 感知 + MCP（40s）

**操作**：

1. Agent 发 **A**：`查一下磁盘和系统负载` → 展示自然语言结论（勿贴长 JSON）  
2. 快捷键 **2** 进工具台，滚动 **白名单工具列表** 3～4 秒（口播提「二十余个运维 Tool」）  
3. 执行一个只读工具后立刻回对话

**口播**：

> 先看感知与插件化。  
> Agent 自动调用磁盘、负载等能力，获取主机实时上下文——对应 OS 深度感知。  
> 清理、重启、进程、网络、systemd、日志等动作，封装为 MCP 工具，由目录扫描注册、调度器统一分发。  
> 模型可以调工具，但只能调授权清单里的工具。

**字幕**：`FR-01 感知` · `FR-02 MCP · 26 Tools 白名单`

---

### 镜 5｜可控清理（80s）★全片高潮之一

#### 5.1 预览（40s）

**操作**：发 **B** `磁盘满了，帮我预览清理临时文件` → 停在 dry-run / 拟清理列表。

**口播**：

> 核心能力来了：可控执行。  
> 用户说磁盘满了、要预览清理。系统走感知与受控清理工具，先给出 **Dry-Run 预览**。  
> 此时文件还没有被真实删除。中风险必须先暴露影响面——这是门控，不是事后道歉。

**字幕**：`Dry-Run · 尚未删除` · `多级门控：确认区间`

#### 5.2 确认（40s）

**操作**：发 **C** `确认执行` → 停在成功结论 / 验证说明。

**口播**：

> 用户明确回复「确认执行」后，信任轮廓提升，系统才写入真实写参数并执行。  
> 随后验证处置是否生效。闭环是：感知、决策、确认、执行、验证。  
> **人机共决，模型不能自己说了算。** 这也避免「AI 声称已删除、实际未执行」的幻觉误导——声明必须有执行证据。

**字幕**：`确认执行 → 真实写` · `人机共决 · 证据一致`

---

### 镜 6｜安全拦截（50s）★全片高潮之二

**操作**：发 **D**（失败换 **D备**）→ 钉死拦截文案 2～3 秒。

**口播**：

> 同样是自然语言，危险指令必须拦在执行前。  
> 我们输入带提示注入特征的破坏性话术，试图诱导 `rm -rf /`。  
> 多级安全门控串联生效：注入检测、意图分级、风险评分、高危命令模式……命中即 **BLOCK**，不会落到磁盘。  
> 这对应赛题的意图校验、确定性，以及抗 Prompt 注入要求。

**字幕**：`FR-03 护栏` · `INJECTION / HIGH_RISK → BLOCK`

---

### 镜 7｜最小权限与路径策略（25s）

**操作**：打开系统配置中路径策略，或安全自检页扫一眼；或纯口播 + 字幕。

**口播**：

> 入口拦不够，执行面还要最小权限：核心动作尽量在受限账户运行，非必要不贯穿 root。  
> 路径白名单限制可读区、可清理根与保护目录，禁止任意路径穿越删除。  
> 权限隔离加路径策略，双保险。

**字幕**：`FR-04 最小权限 · OpsPathPolicy`

---

### 镜 8｜六步审计（45s）★全片高潮之三

**操作**：快捷键 **4** 运维链路审计 → 点开刚才清理或拦截记录 → 慢滑六步。

**口播**：

> 每次关键过程写入运维链路审计。  
> 六个阶段：接收指令、感知环境、推理决策、安全校验、执行结果、效果验证，并用 traceId 串联。  
> 成功套路可沉淀为 AWM 记忆，拦截教训可沉淀为 Reflexion——可追溯，也可复用。  
> Agent 不是黑盒。

**字幕**：`FR-05 六步 CoT` · `接收→感知→推理→校验→执行→验证`

---

### 镜 9｜巡检与产品延展（35s，可剪）

**操作**：发 **E** `一键巡检`（15～20s）→ （可选）效果评分或日志分析闪一下（10s）。

**口播**：

> 在对话之外，系统支持有界巡检与自动修复：低风险经治理准入可自动处置，中高风险仍待确认。  
> 日志分析、运维效果评分、知识库 RAG，构成完整运维工作台。  
> 但无论能力如何扩展，写路径仍须过同一道安全门。

**字幕**：`有界巡检 · 统一门控不变`

## 五、一条龙旁白（整片录音用）

> 企业运维常陷两难：脚本门槛高；AI 一执行又可能误删和注入。赛题要求在麒麟上打造运维 Agent：MCP 负责感知与执行，安全护栏负责可控。ThreshCore 的回答是：自然语言能运维，危险操作控得住，全过程留得下。
>
> 系统采用 B/S 架构。对话、工具台、巡检三条路径统一进入安全门控；不开放 root Shell，只提供白名单 MCP；写操作先预览，确认后执行，全程审计。
>
> 控制台覆盖智能对话、二十六款运维工具、审计溯源、日志分析等能力。主线演示感知、插件化、护栏与溯源。
>
> Agent 可查询磁盘与负载，完成主机感知；运维动作封装为 MCP 工具统一注册调度，模型只能调用授权工具。
>
> 当用户要求预览清理临时文件，系统先 Dry-Run，暴露影响面；用户发送「确认执行」后才真实清理并验证。人机共决，且执行声明与证据必须一致。
>
> 当输入注入型高危指令，多级门控在执行前拦截并拒绝，危险不落盘。再辅以最小权限与路径白名单，从入口到执行面双重约束。
>
> 全过程写入六步链路审计，支持回放；成功经验可沉淀，拦截教训可复用。
>
> 还有有界巡检、日志与效果分析等能力，但写路径始终过同一道门。面向麒麟与 LoongArch 可部署、可验收。
>
> ThreshCore——可控、可确认、可追溯。谢谢各位评委。
