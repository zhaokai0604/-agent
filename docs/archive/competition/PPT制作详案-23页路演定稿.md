### 上屏文字

**页标题**  
`赛题简介：实现目标、价值与技术要求`

**左栏 — 实现目标**

1. 开发部署于**操作系统**的智能运维 **Agent**  
2. 作为**自然语言与 OS 交互的桥梁**  
3. 通过 **MCP（Model Context Protocol）** 协议，使大模型具备：

- 保留对话效率，同时**可追责、可回放**  
- 面向教育/医疗等行业数据中心，**7×24 稳定**优先于「炫技全自动」  

**底栏 — 安全护栏三件套（橙字强调）**

| 组件 | 要点 |
|------|------|
| **意图风险过滤** | 对自然语言指令做风险识别 |
| **最小权限执行代理** | 非必要不用 root |
| **思维链日志审计** | 接收→感知→推理→校验→执行 可追溯 |

**页脚**

### 上屏文字

**页标题**  
`Drain-Plus 算法详解 — 从 GB 级日志到可复用模板`

**五步流程（与 `DrainPlusParser` 源码注释一致）**

| 步 | 名称 | 说明 |
|----|------|------|
| ① | **变量掩码** | UUID、IPv4、浮点、整数等正则替换 → 令牌序列 |

|----|-----------|
| 模型 | `random-forest-v2.onnx`（ONNX Runtime） |

- JVM **不以 root 常驻**  
- `MinPrivilegeExecutor`：`sudo -u award-agent -- <命令>`  
- 配置：`agent.min-privilege.enabled=true`  
- 越权示例：`apt-get install` → Permission Denied  

**C. 推理链路溯源（赛题⑤）**

| 官方五步 | 本系统 `OpsAuditPhases` |
|----------|-------------------------|
| 接收指令 | `receive` |
| 感知环境 | `perceive` |
| 推理决策 | `reason` |
| 安全校验 | `security` |
| 执行结果 | `execute` |
| （扩展） | `verify` |

存储：`ops_audit_trace` · Tab4 输入 traceId 查看 CoT  

**D. 主动巡检与有界修复**

| 项 | 内容 |
|----|------|
| 周期 | Cron 默认每 5 分钟 |
| 检测 | 磁盘、CPU、僵尸进程、日志突增、Drain 新模板 |
| 推送 | WebSocket `patrol_alert` |
| 修复 | 仅白名单 Playbook；HYBRID 模式 &lt;6 分可自动 |
| 边界 | 禁止巡检动态生成任意 Shell |

**E. 非功能落地**  
`GET /api/security/self-check` — 四类探针：未注册工具 · 注入样本 · 高危意图 · 只读/写分离

## 六、29 页扩展（可选 · R3～R8 摘要）

> 仅当评委追问算法细节时启用；插入点后页码顺延，总时长 +4～8 分钟。

| 扩展页 | 标题 | 秒数 | 内容要点 |
|--------|------|------|----------|
| **R3** | 25 维特征与 IntelligentRouter | 40 | `RfFeatureVectorExt` 字段分组；`IntelligentRouter.decide()` 调用链；RuleEngineV2 与 RF 分工 |
| **R4** | evaluate API 现场演示 | 30 | Knife4j 打开 `POST /api/v1/model/evaluate`；粘贴样例 dataset；展示 precision/recall/F1 |
| **R5** | LoongArch ONNX 降级 | 35 | `rf.force-heuristic-on-loongarch`；`EngineHealthEndpoint` 状态；TC-EXT-01 探针 |
| **R6** | AI 诊断 → Agent 受控修复 | 30 | Tab7 报告 → 助手建议 Playbook → 必经 McpInvocationSecurityGate |
| **R7** | 七层安全门动画分解 | 45 | 每层单独一页动画；`AgenticRiskScoreEngine` 阈值 &lt;3 / [3,7) / ≥7 |
| **R8** | 运维效果评分 Tab9 深讲 | 35 | `OpsEffectDashboard`；拦截次数、释放空间、巡检命中 |

**R3 上屏摘要**  
`IntelligentRouter.decide(input)` → 并行 `ruleEngineV2.evaluate` · `randomForestDecisionEngine.evaluate` · `llmDecisionEngine.evaluate` → `ensembleService.fuse`

**R4 请求样例**

```json
{
  "modelVersion": "rf-onnx-v2",
  "dataset": [
    { "features": [0,0,1,0,0, 1.2,0.3,5.0,0.1, ... ], "label": 1 }
  ]
}
```

**R5 降级路径**  
ONNX 加载失败 → `modelStatus=HEURISTIC` → 规则+统计分替代 → Tab 仍显示告警（置信度降低）

**R6 联动链**  
Tab7 异常报告 → 一键「Ask Agent」→ OpsIntentRouter 命中 Playbook → Gate 评分 → 仅 LogCleanupTool 等白名单

**R7 阈值表**

| 分数 | 策略 |
|------|------|
| &lt; 3 | 自动放行（只读）或低风险写 |
| [3, 7) | NEED_CONFIRM + dry-run |
| ≥ 7 | REJECT + 审计 |

**R8 指标**  
`OpsEffectDashboardService`：累计拦截次数 · 释放磁盘 GB · 巡检命中 · 自愈成功率

**插入顺序建议**  
`…11 → R3 → R4 → R5 → R6 → 12…` 或 `…13 → R7 → 14…`；`…15 → R8 → 16…`
